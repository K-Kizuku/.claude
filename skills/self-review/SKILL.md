# 自分の差分を確認する

入力は要件、base/head、作業ツリーの変更、検証証拠。コミット済み・stage済み・未stage・必要なuntrackedを区別する。

1. 差分と関連する既存経路を読み、要件が満たされているか、各変更が依頼に対応するかを確認する。
2. 認可・データ整合性・エラー処理・削除/改名した識別子の参照・設定/docsの更新漏れを、変更の影響に応じて確認する。
3. 指摘を分類する時に[レビュー基準](../../context/review.md)を読む。参照はこのSkillの実体ディレクトリ(symlink先)を基準にする。
4. 根拠のある自分の不具合を修正する。ユーザーの別作業は保持する。不要な依存・未使用の機能・既存保証への再ガードを足さない。
5. 修正で古くなった検証だけverify-changesで更新する。

出力は根拠付きの指摘と対応、残存リスク。小変更は短い確認でよく、指摘0件も正常。完了条件は重大な問題を解消し、証拠が最終差分に対応していること。自分の確認を別モデルによる独立レビューと表示しない。外部投稿・approve・mergeはこのSkillに含まれない。
