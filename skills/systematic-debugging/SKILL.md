# 根本原因を調べる

入力は症状、期待/実際、再現手順、実行環境、直近の変更。足りない情報はまず対象コードやログから確認する。

1. エラー全文と直近の差分を読み、最小の再現を実行する。再現しなければ環境・入力・タイミングの差を観測する。
2. 原因の仮説と根拠を1つ示し、その仮説を区別できる観測を行う。無関係な修正を重ねない。
3. 原因層が分かったら、実装を依頼されている範囲で最小の修正を行う。調査専用の依頼なら結論と修正案までにする。
4. 元の再現手順で解消を確かめ、影響する経路も検証する。反復失敗なら同じ前提を見直す。

出力は再現結果、原因と裏付け、修正、検証結果。原因が未解明なら、分かった境界と次の観測を示す。再現できないものを解決済みとしない。

完了条件は、解消を再現手順で確認し因果を説明できること、または未解明の点と追加観測が具体的であること。修正後の検証はverify-changes、差分の評価はself-reviewの責務。独自の計画承認待ちやsubagentを必須にしない。
